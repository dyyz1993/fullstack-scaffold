# ISR / SSR / SSG 指南 —— 场景选择与工作原理

> 本文档面向接手者：什么时候用模板的哪个渲染能力、三条部署链各自行为、
> 以及「高流量 + SEO + 动态内容」场景（如技能收录站）为什么选 ISR。

## 1. 三种渲染模式一览

| 模式                    | 渲染时机                                   | 适用场景                    | 本模板的支持                               |
| ----------------------- | ------------------------------------------ | --------------------------- | ------------------------------------------ |
| **SSG**（静态生成）     | 构建时全量预渲染                           | 内容几乎不变的落地页/文档   | vite 插件 prerender（可选，需本地 Chrome） |
| **SSR**（服务端渲染）   | 每次请求实时渲染                           | 个性化内容、实时性要求高    | ISR 管线内部使用（见下）                   |
| **ISR**（增量静态再生） | **首次访问时渲染 + 缓存 + 内容变更时失效** | **高流量 + SEO + 动态内容** | ✅ 完整实现（本文重点）                    |

## 2. ISR 工作原理（本模板实现）

```
用户首次访问 /content
   └→ miss ──→ 现场渲染 HTML（React SSR + 数据）──→ 写入缓存 ──→ 返回
后续访问
   └→ fresh ──→ 直接返回缓存 HTML（毫秒级，不跑 React、不查库）
内容创建/更新（content-service 内自动触发）
   └→ purge ──→ 清除相关缓存 ──→ 下次访问重新渲染
缓存超过 maxAge
   └→ stale ──→ 先返回旧页面，后台静默重渲染（stale-while-revalidate）
```

关键点：**你不需要「每加一条内容就手动重新生成」**——`content-service.ts`
在创建/更新/删除时自动调用 `purgeContentPages()`，失效是挂好的。

## 3. 场景决策：技能/内容收录站（高流量 + SEO + 动态）

这正是 ISR 的教科书场景：

- **高流量** → fresh 命中直接吐缓存，单 Worker 可扛海量请求
- **SEO** → 首次访问的 SSR HTML 含真实内容（链接、标题、正文），爬虫可抓取
- **动态内容** → 发布/编辑自动失效，新内容下次访问即生效
- **不可能每次全站重建**（传统 SSG 的痛点）→ ISR 只按需渲染被访问的页面

反例（不该用 ISR 的场景）：

- **管理后台 / 登录后内容** → 爬虫拿不到东西，ISR 无意义（模板的 admin 就是纯 SPA）
- **强个性化页面**（用户 A 和 B 看到不同）→ 缓存会串内容，用纯 SSR/CSR

## 4. 三条部署链的渲染行为差异（重要！）

| 部署方式                    | SSR                        | ISR            | 说明                            |
| --------------------------- | -------------------------- | -------------- | ------------------------------- |
| **Node（npm start）**       | ✅（0.5.x 起入口内置 ISR） | ✅             | `entries/node.ts` 的 ISR 中间件 |
| **Cloudflare Workers**      | ✅                         | ✅（生产推荐） | Cache API 存储 + 自动失效       |
| **Vite dev（npm run dev）** | ❌（纯 SPA）               | ❌             | 开发时客户端渲染，调试用        |

## 5. SSR 水合架构（0.5.3+）

服务端：`entry-server.tsx` → 按 `ssr-pages.ts` 静态组件映射渲染真实页面
内容（非 lazy 壳），数据经 `isr-renderer` 注入 `window.__SSR_DATA__`。

客户端：`main.tsx` 检测 `#root` 有子节点 → `hydrateRoot`（复用服务端
HTML，不重画）；无 SSR 标记时回退 `createRoot`。

页面首帧：`ContentListPage`/`ContentDetailPage` 从 `__SSR_DATA__` 读
初始数据（水合一致、无闪白），`useEffect` 再自行刷新。

### 新增一个需要 SEO 的页面（3 步）

1. `src/client/ssr-pages.ts` 注册路由 → 静态导入的组件
2. 页面组件加 `__SSR_DATA__` 首帧读取（参照 ContentListPage）
3. 模块 `isr.ts` 的 fetch 返回该页数据（自动进 `__SSR_DATA__`）

## 6. 已知限制

- 仅 ISR 路由有页面级 SSR（`isrRegistry` 注册的路径）；其余路由 SSR 输出
  布局壳 + meta（合理：管理页不需要 SEO）
- hydrateRoot 要求服务端/客户端组件树一致——页面里避免在首帧渲染
  `Date.now()`/随机数等非确定内容
- vite dev 模式不走路由级 SSR（调试 SEO 请用 `npm run build && npm start`）
