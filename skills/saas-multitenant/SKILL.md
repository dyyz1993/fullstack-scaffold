# SaaS Multi-Tenant (create-fullstack-scaffold saas preset)

Operating guide for multi-tenant apps generated by `npx create-fullstack-scaffold --preset saas`.

## When to Use

Use when:

- Working on an app generated with the `saas` preset (has `module-tenant`, `src/tenant/`, `tenants` table)
- Adding tenant-scoped features (new business tables with `tenant_id`, member-visible pages)
- Debugging tenant isolation, invitation flow, quota rejections, or the tenant console (`/tenant/*`)
- Operating the platform side (tenant CRUD, quota fields, CLI commands)

Do NOT use for: single-user apps (use `todo-app` preset), billing/Stripe integration (not built), SSO/SCIM (not built).

## Core Concepts

```
Platform super_admin ── tenant CRUD / plan / quota fields (API requires super_admin role)
Tenant admin (tenant_admin) ── invite members / assign roles / custom roles (quota-limited by plan)
Members (tenant_member / tenant_guest) ── role-scoped data access
```

Provisioning is transactional: `POST /api/tenants` creates tenant + seeds 3 system roles
(admin=full, member=read-write, guest=read-only) + owner joins as admin.

Invitation: `POST /tenants/:id/members/invite` → 7-day token → public landing
`/tenant/invite/:token` → accept (transactional, idempotent re-activation).

## Key Endpoints

| Domain      | Endpoints                                                                                   |
| ----------- | ------------------------------------------------------------------------------------------- |
| Tenant      | `GET/POST /tenants`, `GET /tenants/mine`, `GET /tenants/slug/{slug}`, `GET /tenant/current` |
| Members     | `GET /tenants/{id}/members`, `POST .../members/invite`, `PUT/DELETE .../members/{memberId}` |
| Roles       | `GET/POST /tenants/{id}/roles`, `PUT/DELETE .../roles/{roleId}`                             |
| Invitations | `GET /tenants/invitations/{token}` (public), `POST .../accept`                              |

Quota enforcement (server-side, real): member count vs `max_users` checked at invite AND accept;
custom role count vs `PLAN_ROLE_LIMITS` (free 3 / starter 5 / pro 10 / enterprise ∞) checked at create.

## Console & Auth

- Console entry: `/tenant/login` (platform account + `/tenants/mine` tenant pick)
- Invite landing: `/tenant/invite/:token` (public, sanitized detail)
- Tenant identification: `X-Tenant-Slug` header or subdomain; **absent → global mode (pass-through)**, unknown slug → 404
- First boot seeds `superadmin/admin123` (role `super_admin`) — logged as WARN, change before production

## Pitfalls (hard-won)

1. **Zustand v5 SSR snapshot = `getInitialState()`** — `setState` seeding is invisible to
   `renderToString`. First-paint data must come from `globalThis.__SSR_DATA__` (set by
   entry-server during render; browser hydration reads the same key via `window`).
2. **libsql `:memory:` + transactions** — `transaction()` nulls the internal connection;
   next query reopens a FRESH empty db on `:memory:`. Tests must use temp files
   (`src/test/setup-db-path.ts`).
3. **push-built db + migrate replay** — `db:push` creates tables without the drizzle
   journal; `runMigrations` then crashes on CREATE TABLE. Driver stamps the journal
   automatically when it detects "business tables exist + journal empty".
4. **Auth context keys** — platform auth sets `c.authUser`; tenant middleware sets
   `c.tenant` (optional). Non-member → 403 via `requireTenantMembership`.
5. **Quota errors are ValidationErrors (400)** with Chinese messages — do not retry.

## Verification Recipe

After any tenant-domain change:

```bash
npx tsc --noEmit                          # types
npx vitest run src/server/module-tenant   # domain tests (31+)
npm run build && PORT=3010 npm start      # prod boot (migrations auto-apply)
curl localhost:3010/api/todos             # seeded (25 items, no manual db:push needed)
# invite chain: create tenant → invite → GET invitation (no auth) → accept → members → remove → 403
```

Deployed-service check: health probe alone is NOT enough — add a 10+ minute survival
watch (push-built db migration issues kill services minutes after the health window).
